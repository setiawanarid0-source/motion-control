The main `minimaxH3Akatz` web selection now builds the owner's saved Turbo8 /
three-frame candidate, instead of the previous V8 four-step builder. The owner
explicitly requested deployment so that the next visual trial can run in Vanta.

## Output delivery

MP4 preview/download still uses the original video ZIP and existing archive
recovery. ZIP 5108 contains first/middle/last PNGs from the same final IMAGE batch.
The result and Motion History expose a separate three-frame download.

Web history can omit node IDs and filenames. `output-archive-roles.js` resolves
that case from the ZIP directory contents: one MP4 archive and one three-PNG
archive. It prefers HTTP range reads, coalesces/caches lookups, and supports
servers without ranges with a temporary-disk fallback. It never extracts,
re-encodes or generates media. Ambiguous archives are rejected rather than guessed.

`/api/tasks/:taskId/frames` uses the same owner/account-scoped task access, encrypted
retained task credential, and 72-hour access expiry. It does not submit inference.

## Evidence and boundaries

The new checks cover source-template parity over all 357 accepted frame counts,
symbolic complete-frame delivery, first/middle/last indices from the actual output,
silent/audio inputs, four aspect ratios, unchanged typed seeds, uploaded receipt
reuse, editor round-trip and HTTP download. ZIP delivery checks cover anonymous
and shuffled outputs, ZIP64/comments, range and full-stream fallback, authorization,
caching and expiry. Existing six-workflow token-submission tests explicitly
verify that Akatz v3 retains Turbo4 while the main selection uses Turbo8.

`npm run check` is the required application check and runs these checks as well
as the pre-existing suite. These CPU/HTTP checks do not qualify GPU rendering,
visual texture, facial mimicry, duration on a real worker or generation cost.
Those remain pending the owner's next web generation.
